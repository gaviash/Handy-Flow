# Plan A — Fournisseurs configurés une fois, modèle choisi par fonction

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Configure every provider and its models in one place (Settings → Models), then pick provider + model for each AI feature: rewrite, rewrite fallback, learning validator, speech API.

**Architecture:** A new pure module `src-tauri/src/features.rs` owns the per-feature choice (`FeatureModels`), its one-shot migration from today's scattered fields, and the single resolver `feature_target`. Every caller that resolves a provider today (rewrite, fallback, judge, speech API) goes through it. The frontend gets two new cards on the Models page; the old provider menus become summaries with a link.

**Tech Stack:** Rust (Tauri 2, specta bindings), React + TypeScript + Zustand, i18next, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-19-providers-per-feature.md` (read it first). Plan B (`2026-11-19-B-wispr-parity-absorption.md`) depends on this plan's `Feature::LearningValidator`.

## Global Constraints

- Keys never leave the `SecretMap` vault: not in `settings_store.json` in clear, not in logs, not in `bindings.ts`.
- Migration is silent, one-shot (`features_migrated: bool`), and keeps the old fields readable (downgrade possible).
- No behaviour change for a user who touches nothing: after migration every feature resolves to exactly the provider + model it used before.
- All user-facing strings via i18next (`en` + `fr` written, other locales get the English value; `bun run check:translations` must pass).
- `cargo fmt`, `cargo clippy` clean on touched code; conventional commits.

## Review Focus

1. A user whose judge ran on Groq's spare model while rewriting on OpenAI keeps that exact pair after migration (Task 1 test `migration_freezes_the_judge_groq_spare_model`).
2. Removing the provider a feature uses is refused with the feature names, never leaves a dangling choice (Task 3 test).
3. A speech-API choice whose model disappears falls back to "local model only" and warns, never sends audio to a chat model (Task 2 test `speech_feature_only_accepts_speech_models`).
4. "Automatic" for the validator follows the rewrite **live**: changing the rewrite model changes the validator without a second save (Task 2 test).
5. Rewrite turned off (`post_process_enabled = false`) disables the Automatic validator but not an explicitly chosen one (today's rule in `judge_target`, kept).

### Task 2: One resolver for every feature

**Files:**
- Modify: `src-tauri/src/features.rs` (add resolver), `settings.rs:1467` (`active_post_process_provider` reads `features.rewrite`), `actions.rs:157, 236, 454` (rewrite model + fallback via the resolver), `judge.rs:170` (`judge_target` becomes a thin wrapper over `feature_target(s, LearningValidator)`), `cloud_asr.rs:84` (`configured` via `feature_target(s, TranscriptionApi)`)

**Interfaces — Produces:**
```rust
pub type Target = (PostProcessProvider, String /*key*/, String /*model*/);
pub fn feature_target(s: &AppSettings, f: Feature) -> Option<Target>
pub struct FeatureStatus { pub feature: Feature, pub provider_label: Option<String>, pub model: Option<String>,
                           pub automatic: bool, pub problem: Option<FeatureProblem> }  // Type, Serialize
```

Rules: a key is required except for `custom`; `LearningValidator` with an empty choice = Automatic = `feature_target(Rewrite)`, and `None` when `post_process_enabled` is false (today's rule); `TranscriptionApi` only accepts a model with `speech: true`, the others only `speech: false`; `LearningValidator` keeps today's `api_format == OpenAi` requirement (structured JSON).
